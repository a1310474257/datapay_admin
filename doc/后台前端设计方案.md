## 一、背景与目标

DataPay 是一个围绕"课程 + HR 工具 + 调研报告 + 活动 + 商品"的付费平台，C 端已有小程序项目 `datapay_ui`，数据库共 **28 张 `dp_*` 表**（见 `datapay_ui/doc/数据库设计文档.md`）。

本项目 `datapay_admin` 是该平台的**后台管理系统**，提供运营、用户、课程、资源、活动、商品、订单等全链路管理能力。

### 当前阶段目标

1. **不依赖后端**，纯前端跑通全部管理页面
2. 数据全部来自本地 Mock（内存 + 工厂函数生成）
3. 页面与 DB 字段完全对齐，方便后期切换真实后端（仅改 `api/*.js` 的实现）

### 范围外

- 国际化（i18n）
- PWA / 离线
- 复杂的 SKU 独立库存与价格（DB 当前未设计 SKU 表）
- 操作日志审计（P3 可选）

## 二、关键决策

| # | 决策项 | 结论 | 说明 |
|---|---|---|---|
| D1 | Mock 方式 | **本地函数**（不用 MSW） | `api/*.js` 内部直接调 `mockApi.*` 读内存 DB |
| D2 | Mock 数据持久化 | **不持久化** | 每次刷新重新 seed，阶段性可控 |
| D3 | P0 课程详情范围 | **简化版** | 只做 Tab1 基本信息，章节/资料延到 P1 |
| D4 | 价格字段单位 | 传输"分"、展示"元" | DB 字段为 `INT UNSIGNED`，统一用 `PriceInput` 组件转换 |
| D5 | 时间格式 | `YYYY-MM-DD HH:mm:ss` 字符串，时区 `+08:00` | — |
| D6 | 管理员账号 | 固定 `admin / admin`（mock） | DB 缺 `dp_admin_user` 表，联调前由后端补 |
| D7 | 退款流程 | 前端只提交审批，异步退款由后端处理 | Mock 层用 `setTimeout` 模拟状态变更 |
| D8 | 活动状态 | `upcoming / enrolling / ended` 由后端/mock 返回 | 前端不本地计算，避免时区问题 |

## 五、全局规范

### 5.1 接口层（`request.js`）

**请求拦截**
- 注入 `Authorization: Bearer <token>`
- 注入 `X-Request-Id`
- GET 参数清理 `undefined / ''`

**响应拦截**
- `code === 0` → 直接返回 `res.data.data`
- `code === 1002`（未登录）→ 清 token → 跳 `/login?redirect=...`
- `code === 1003`（权限不足）→ `ElMessage.error` + 停留
- 其他非零 → `ElMessage.error(message)` 并 `reject`
- HTTP 非 2xx → 统一提示"网络异常，请稍后重试"

### 5.2 列表接口统一契约

**请求**：`{ page, pageSize, keyword, ...filters, sort? }`
**响应**：`{ list: [], total, page, pageSize }`

### 5.3 价格规范

- **传输**：全部以「分」为单位
- **展示**：`¥ 0.00`（两位小数）
- **录入**：`<PriceInput v-model="form.price" />`，v-model 绑定的是**分**，内部展示**元**
- **工具**：`fen2yuan(1234) → '12.34'`、`yuan2fen('12.34') → 1234`（整数运算避免浮点误差）

### 5.4 枚举（`utils/enums.js`）

见 [附录 A](#附录-a枚举字典)。配合 `<StatusTag :dict="..." :value="row.status" />` 全站复用。

### 5.5 权限模型（最小可用）

| 概念 | 粒度 | 来源 |
|---|---|---|
| 菜单权限 | 模块级 | `GET /admin/menus` 返回树，驱动动态路由 |
| 按钮权限 | `resource:action` 字符串 | `GET /admin/me` 返回 `permissions: string[]` |

命名约定：`order:list / order:ship / order:cancel / refund:approve / user:ban / course:publish ...`

使用：
- 指令：`<el-button v-permission="'refund:approve'">同意退款</el-button>`
- 函数：`hasPerm('refund:approve')`

### 5.6 错误码

复用 `datapay_ui/doc/接口文档.md` 定义的错误码：

| code | 说明 |
|---|---|
| 0 | 成功 |
| 1001 | 参数错误 |
| 1002 | 未登录 / token 失效 |
| 1003 | 权限不足 |
| 1004 | 资源不存在 |
| 1005 | 操作失败 |
| 5000 | 服务器内部错误 |

## 六、Mock 数据方案

### 6.1 总体思路

**不使用 MSW**，而是：

1. `src/mock/` 只做**数据层**（内存表 + 工厂 + seed）
2. `src/api/*.js` 每个函数内部走开关：
   - `VITE_USE_MOCK === 'true'` → 调 `mockApi.*` 读内存 DB
   - 否则 → 调 `request.js` 打真实后端
3. **业务组件的调用方式永远不变**，后期切真实后端只需删掉 mock 分支

### 6.2 通用 CRUD 工具（`mockApi.js`）

```js
// 伪代码示意
export const mockApi = {
  async crud(table, params, { searchFields = [], filterFields = [], defaultSort } = {}) {
    await delay(150)
    let rows = [...table]
    if (params.keyword) {
      rows = rows.filter(r => searchFields.some(f => String(r[f] || '').includes(params.keyword)))
    }
    filterFields.forEach(f => {
      if (params[f] !== undefined && params[f] !== '') {
        rows = rows.filter(r => r[f] === params[f])
      }
    })
    // 排序、分页切片...
    return { list: paged, total, page, pageSize }
  },
  async create(table, data) { /* 分配 id / created_at，push */ },
  async update(table, id, data) { /* 按 id 合并 */ },
  async remove(table, id) { /* splice */ },
  async findById(table, id) { /* find */ },
}
```

**25+ 个简单 CRUD 页面调用示例**：

```js
// src/api/category.js
export const getCategoryList = (params) =>
  mockApi.crud(db.category, params, { searchFields: ['name'], filterFields: ['status'] })

export const createCategory = (data) => mockApi.create(db.category, data)
export const updateCategory = (id, data) => mockApi.update(db.category, id, data)
export const deleteCategory = (id) => mockApi.remove(db.category, id)
```

### 6.3 种子数据（`seed.js`）

- `main.js` 启动时按 `VITE_USE_MOCK` 条件执行 `seed()`
- 工厂函数生成符合 DB 字段的对象（字段名、类型、枚举值完全一致，金额为"分"）
- 数据之间**关联真实**：`course.teacher_id` 指向存在的讲师、`order.order_items` 指向真实商品/课程等

### 6.4 Mock 数据约定

| 约定 | 说明 |
|---|---|
| 金额 | 整数「分」，`faker.number.int({ min: 100, max: 99900 })` |
| 时间 | `dayjs(faker.date.past()).format('YYYY-MM-DD HH:mm:ss')` |
| 订单号 | `DP${YYYYMMDD}${4位序号}`，保证唯一 |
| 图片 | `https://picsum.photos/seed/<id>/800/450`（按 id 稳定）|
| 视频 | 公共示例 mp4 或留空 |
| 富文本 | 3~5 段 `<p>` + 1 张 `<img>` |
| 枚举值 | 完全照搬 DB 文档 |
| 关联完整性 | seed 阶段保证 |
| 动态字段 | `activity.activity_status` 由 mock handler 按当前日期实时算 |

## 八、Pinia Store 设计

| Store | state | actions | 持久化 |
|---|---|---|---|
| `user` | `token / profile / permissions` | `login / logout / fetchProfile` | `token` 持久化 |
| `permission` | `menus / dynamicRoutes / generated` | `generateRoutes(menus)` | 否 |
| `app` | `sidebarCollapsed / device / theme` | `toggleSidebar / setTheme` | `collapsed` 持久化 |
| `tagsView` | `visitedViews / cachedViews` | `addView / delView / delOthersViews / delAllViews` | sessionStorage |
| `dict` | `category[] / teacher[] / expressCompany[]` | `loadCategory / loadTeacher / loadExpress`（带缓存 + TTL） | sessionStorage |

### `permission.generateRoutes` 流程

1. 登录后 `user.fetchProfile` 拿 `permissions[]`
2. `GET /admin/menus` 返回模块树
3. 前端本地维护 `asyncRoutes`，按后端返回的 menus 过滤
4. `router.addRoute()` 动态注入
5. 未命中路由 → 404 页（避免白屏）

### `tagsView` + `<keep-alive>` 避坑

- 详情页 `/course/detail/:id` 不纳入 `keep-alive`（避免串 id）
- 或使用 `:include` 时按 `name + id` 拼 key，刷新时显式清缓存

## 十三、后台接口契约草案

> 后续与后端评审此清单，产出正式 `后台接口文档.md`。以下所有 URL 前缀 `/admin`，复用 `datapay_ui/doc/接口文档.md` 的统一响应格式与错误码。

### 13.1 必备接口清单

| 模块 | 接口 |
|---|---|
| 鉴权 | `POST /admin/login` / `POST /admin/logout` / `GET /admin/me` / `GET /admin/menus` |
| 上传 | `POST /admin/upload`（返回 `{ url, size, type }`）/ `POST /admin/upload/video`（大文件） |
| 统计 | `GET /admin/stats/overview` / `GET /admin/stats/gmv-trend` / `GET /admin/stats/order-type` / `GET /admin/stats/top-courses` |
| CRUD 五件套 | `GET /admin/<模块>` / `GET /admin/<模块>/:id` / `POST /admin/<模块>` / `PUT /admin/<模块>/:id` / `DELETE /admin/<模块>/:id` |
| 课程嵌套 | `GET/POST/PUT/DELETE /admin/course/:id/chapter`、`/lesson`、`/material` |
| 商品嵌套 | `PUT /admin/product/:id/images`、`PUT /admin/product/:id/specs`（整组 PUT，事务由后端） |
| 活动嵌套 | `/admin/activity/:id/speaker`、`/admin/activity/:id/register`（含 `PUT /:id/check-in` 批量签到） |
| 订单 | `POST /admin/order/:id/ship` / `POST /admin/order/:id/cancel` / `PUT /admin/order/:id/remark` |
| 退款 | `POST /admin/refund/:id/approve` / `POST /admin/refund/:id/reject` |
| 用户 | `POST /admin/user/:id/ban` / `POST /admin/user/:id/unban` / `POST /admin/user/:id/force-logout` |
| 导出 | `POST /admin/<模块>/export` → `taskId`；`GET /admin/export-task/:id` → `status + downloadUrl` |
| 字典 | `GET /admin/dict/express-company` |

### 13.2 强约束

1. 所有列表接口**必须支持** `?page=&pageSize=&keyword=`
2. 所有金额字段以**分**传输
3. 所有时间字段以 `YYYY-MM-DD HH:mm:ss` 字符串传输，时区 `+08:00`
4. 订单按 `status` 分组数量**单独给**：`GET /admin/order/status-count` → `{0:12, 1:3, ...}`
5. 活动状态 `activity_status` 由后端在列表/详情直接返回字符串
