## 执行建议

- **串行执行**（推荐）：批次间有强依赖，后批次直接消费前批次的产出（基础设施 → 公共组件 → 业务页面），串行最稳。
- **并行执行**（不推荐）：只有在严格冻结"契约接口"后才可行，否则会出现 mock 接口/组件 API 不一致返工。

## 每份文档的统一结构

1. **前置条件**：上一批次必须完成的产出清单
2. **任务清单**：按依赖顺序编号的子任务
3. **文件产出清单**：本批次需要新建/修改的文件
4. **关键实现细节**：必须遵守的代码约定（字段对齐、mock 契约、组件 Props…）
5. **验收标准**：每个子任务完成的可观察条件
6. **交接物**：下一批次会依赖的稳定契约
7. **风险与注意事项**

## 全局规范（所有批次通用）

- 技术栈：Vue 3 + Vite 5 + Element Plus（`zhCn`）+ Pinia + Vue Router 4 + SCSS
- 开发端口：`5190`，host `0.0.0.0`，路径别名 `@` → `src/`
- 价格：传输"分"（整数），展示"元"
- 时间：`YYYY-MM-DD HH:mm:ss`，时区 `+08:00`
- 枚举：见设计方案 [附录 A](../后台前端设计方案.md#附录-a枚举字典)
- 列表接口契约：请求 `{ page, pageSize, keyword, ...filters, sort? }`；响应 `{ list, total, page, pageSize }`
- Mock 开关：`VITE_USE_MOCK=true` 时走内存 DB，否则走真实后端
- 命名约定：视图 `views/<模块>/index.vue`（kebab-case 模块名）；组件大驼峰；Store 小驼峰；路由 `name` 大驼峰

## 开始前必读

在开始任一批次前，agent 应：

1. 阅读 [`../后台前端设计方案.md`](../后台前端设计方案.md) 对应章节
2. 阅读 `.cursor/rules/` 下的四条项目规则（project-architecture / state-and-router / ui-style-conventions / vue-component-patterns）
3. 参考 `datapay_ui/doc/数据库设计文档.md`（28 张 `dp_*` 表的字段定义）——**mock 字段必须 1:1 对齐 DB**
