# 第 4 批 · P1 + P2 补齐（含可选 P3）

> 工期：约 **4~5 天**（P1 ~3 天 + P2 ~2 天 + P3 可选 ~0.5 天）
> 设计依据：[`../后台前端设计方案.md`](../后台前端设计方案.md) §十、§十一

## 一、本批目标

在前三批打下的基础设施、公共组件、P0 业务闭环之上，**补齐剩余 17+ 个页面** 与 **6 个进阶组件**，实现设计方案全部功能（P3 可选），使系统具备完整运营管理能力。

## 二、前置条件

第 1、2、3 批均已验收通过。具体依赖：

- 第 3 批演示脚本能完整走完
- `window.__db` 28 张表数据完整；mock CRUD 稳定
- 9 个 P0 组件稳定、可扩展
- 动态路由 + 权限按钮 + 菜单注入工作正常
- 订单/课程/用户的 P0 页面预留了 P1 扩展点

## 四、P1 阶段（~3 天）

### 4.1 新增 4 个组件

| 组件 | 关键 Props | 用途 |
|---|---|---|
| `UploadImageList` | `v-model:urls, sortable, maxCount, folder` | `dp_product_image` 多图轮播 |
| `TargetPicker` | `type(1/2/3/4), v-model:id, v-model:title` | Banner 跳转目标选择 |
| `SpecEditor` | `v-model: [{ id,name,sort, values:[{id,value,sort}] }]` | 商品规格组/值嵌套增删 |
| `ChapterLessonTree` | `courseId, v-model:tree` | 章节 + 课时两层拖拽 |

**关键实现点**：

- `UploadImageList`：基于 `<el-upload>` 和 `vuedraggable`（同 `v-model:urls`），点击预览、单张删除、拖拽排序
- `TargetPicker`：按 `type` 动态加载不同字典（课程/活动/商品/HR工具），用 `<el-dialog>` + `ProTable` 搜索选择；选中后 emit `update:id` + `update:title`
- `SpecEditor`：上下两层折叠卡片；规格组可增删+排序；每组 values 数组同样可增删+排序；输出干净数据
- `ChapterLessonTree`：基于 `vuedraggable` 嵌套（chapter list + 每 chapter 的 lesson list）；课时字段：`title / duration_sec / video_url / is_free / sort`

### 4.2 新增/完善 11 个页面

#### 4.2.1 课程详情 Tab 扩展（`/course/detail/:id`）

- **Tab2 章节课时**：用 `<ChapterLessonTree>`；新增章节 / 课时 / 拖拽排序 / 批量保存
  - API：`api/course.js` 新增 `getChapters(courseId)`、`saveChapters(courseId, tree)`
  - 课时视频用 `<UploadFile accept=".mp4" autoExtractMeta>`，meta 抽取后写入 `duration_sec`
- **Tab3 配套资料**：`<ProTable>` 列：标题 / 类型 / 大小 / 下载链接 / 排序 / 操作
  - 编辑弹窗：title / type(PDF/DOCX/ZIP/MP4) / file（UploadFile）/ sort
  - API：`api/course.js` 新增 `getMaterials(courseId)`、`saveMaterial(courseId, data)`、`deleteMaterial(id)`

#### 4.2.2 用户详情抽屉子 Tab（`/user/list` 的详情）

补 4 个子 Tab：

- **已购课程**：列表 `dp_user_course` join `dp_course`（课程名/购买时间/进度）
- **已购资源**：`dp_user_resource` join `dp_resource`
- **收货地址**：`dp_user_address`
- **订单列表**：过滤 `dp_order` by `user_id`

#### 4.2.3 订单发货弹窗 + 相关操作（`/order/list`、`/order/detail/:id`）

- **发货弹窗**：选快递公司（`DictSelect dictKey="express"`）+ 快递单号；提交调 `shipOrder(id, { express_company, express_no })`
- **修改运单**：`status=2` 时弹同样的弹窗（预填当前值）
- **备注弹窗**：文本域；实际更新 `dp_order.remark`
- **跳退款审核**：`status=4` 的订单，"查看退款"按钮跳 `/order/refund?order_id=xxx`

#### 4.2.4 运营管理 3 页

| 路径 | 表 | 要点 |
|---|---|---|
| `/operation/banner` | `dp_banner` | 用 `TargetPicker`；type 切换清空 target_id；UploadImage 3:1 |
| `/operation/notice` | `dp_notice` | 标题 + 富文本内容（`RichEditor`） + 发布时间 + 状态 |
| `/operation/hot-search` | `dp_hot_search` | 关键字 + 排序 + 状态 + 点击量 |

#### 4.2.5 `/resource/list` - 资源管理（`dp_resource`）

- 顶部 Tab 切 `resource_type`（1=HR工具 / 2=调研报告）→ `setParams({ resource_type: tab })`
- 表单字段：title / cover / resource_type / file_type（PDF/DOCX/ZIP/MP4）/ file（UploadFile，自动抽 size/pages）/ preview_url（预览文件）/ preview_pages / original_price / price / update_time（DatePicker，DB DATE）
- 交互：`original_price === 0` → "免费资源" 提示，`price` 置灰且强制 0
- 免费判断基于**输入时实时响应**

#### 4.2.6 商品管理 2 页

- **`/product/list`**：列表（cover / title / category / 规格数 / price / stock / sales / status / 操作）
- **`/product/detail/:id`**：3 Tab
  - Tab1 基本信息：category / title / cover / brief / description（RichEditor）/ price / original_price / stock / status
  - Tab2 轮播图：`<UploadImageList v-model:urls="form.images" sortable maxCount="10">`
  - Tab3 规格：`<SpecEditor v-model="form.specs">`
- API：`api/product.js`：`getProductList / findProductById / createProduct / updateProduct / deleteProduct / saveImages / saveSpecs`
- ⚠️ 当前 DB 无 SKU 独立库存/价格，**所有规格组合共享 `product.price / stock`**；界面加提示文案

#### 4.2.7 `/order/refund` - 退款审核（`dp_refund`）

- 顶部 Tab：待审批(0) / 已通过(1) / 已拒绝(2)，带徽标
- 列：`refund_no / order_no / user / amount(元) / reason / status / created_at / 操作`
- 详情抽屉：订单快照 + 原因 + 审批历史
- 操作：同意 → `POST /refund/:id/approve` / 拒绝 → `POST /refund/:id/reject` + 拒绝原因
- **Mock 异步**：审批后 `setTimeout(() => status 转终态, 3000)`
- **前端 3s 轮询**：进入"待审批"或"审批中"详情抽屉后，`setInterval(fetchDetail, 3000)` 直到 status 终态；列表也 3s 刷新直到列表无审批中项

## 七、全局注意事项（跨页面）

1. **订单时间轴**：`/order/detail/:id` 如果 P3 要补操作日志，可扩展时间轴
2. **导出异步模式**：活动、订单都要用异步任务 + 轮询，避免前端计算大量数据
3. **ECharts 内存**：离开仪表盘路由必须 dispose，否则切换标签页内存泄漏
4. **大表性能**：`dp_lesson_progress` 1000 条、`dp_order` 400 条 mock 性能还好；如果扩大规模需优化 mockApi 搜索
5. **弹窗组件统一**：复杂弹窗放在 `views/<模块>/components/` 下，保持 `views/<模块>/index.vue` 简洁
6. **`v-permission`**：新按钮都加权限码，mock `permissions` 补全
7. **富文本存储**：statement 原样保存 HTML；渲染时若有 XSS 担忧可用 DOMPurify（可选）
