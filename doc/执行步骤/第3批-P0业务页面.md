# 第 3 批 · P0 业务页面（简化版）

> 工期：约 **4 天**
> 设计依据：[`../后台前端设计方案.md`](../后台前端设计方案.md) §十、§十一

## 一、本批目标

实现 **11 个 P0 页面**，覆盖"用户 → 课程 → 订单"核心业务闭环的**浏览与基础维护**能力。完成后可对干系人演示：登录 → 仪表盘 → 维护分类/讲师/课程 → 浏览用户/订单 → 改密码。

P1/P2/P3 的页面与高级交互（章节编辑、发货弹窗、退款、活动、商品、报表图表等）留给第 4 批。

- 第 1 批：`mockApi / utils / stores / router / permission / layout` 全部可用；`window.__db` 28 张表有数据

## 四、各页面详细规格

### 3.1 `/login` - `views/login/index.vue`

- 表单字段：`username` / `password`
- 固定校验：必填、长度
- 提交 → `userStore.login({ username, password })`
- 成功 → `router.push(route.query.redirect || '/dashboard')`
- Mock 实现（在 `api/admin.js`）：`admin/admin` 通过，其他返错
- 回车触发提交；记住 `username` 到 localStorage（可选）

### 3.2 布局与菜单接入

- `permission.js` 守卫登录成功后调 `getMyMenus` → `permissionStore.generateRoutes` → `addRoute`
- `Sidebar.vue` 消费 `permissionStore.menus` 递归渲染 `<el-menu-item>` / `<el-sub-menu>`
- 点击菜单 → 跳转 + `tagsViewStore.addView`
- 当前激活菜单高亮（按 `route.path` 匹配）
- 折叠态 icon-only

### 3.3 `/dashboard` - `views/dashboard/index.vue`

**只做 5 个数值卡片**（图表留给第 4 批 P2）：

| 卡片 | 数据来源（mock） |
|---|---|
| 今日新增用户 | `db.user.filter(u => u.created_at.startsWith(today)).length` |
| 今日订单数 | 同上筛 `db.order` |
| 今日 GMV | `db.order.filter(今日+已付款).reduce(+actual_pay)`，转元 |
| 待审批退款 | `db.refund.filter(status===0).length` |
| 待发货订单 | `db.order.filter(status===1 && order_type===5).length` |

- 新建 `src/api/stats.js`：`getOverview()` 返回上述 5 个数
- 页面：5 张卡片 Grid 布局（`<el-col :span="4.8">` 或自定义 5 列）
- 卡片样式：图标 + 标题 + 大数字 + 同比占位（可不做）

## 六、关键实现细节

1. **路由 meta**：每个路由加 `{ title, permission?, keepAlive?, icon? }`，`Breadcrumb` 与 `TagsView` 消费之
2. **详情页 keep-alive 避坑**：`/course/detail/:id`、`/order/detail/:id` **不纳入 cachedViews**
3. **列表页默认进 keep-alive**，返回列表时分页/筛选状态保留
4. **权限按钮**：mock `permissions` 数组包含所有 P0 按钮权限码
5. **脱敏**：手机 `138****1234`、openid 中段打星
6. **金额展示**：一律用 `fen2yuan`；单元格统一 `¥ 0.00`
7. **时间展示**：直接用字符串，不要二次 dayjs 格式化（已是 `YYYY-MM-DD HH:mm:ss`）
8. **表单提交 trap**：保存按钮 `:loading="submitting"`，防重复点击
9. **ProTable 切换状态 Tab**：通过 `tableRef.setParams({ status: currentTab })`，再 `refresh()`
10. **徽标 count**：`getOrderStatusCount` 返 `{ 0: n0, 1: n1, ... }`，Tab 组件独立维护一份 reactive
11. **Mock 字典缓存刷新**：讲师/分类新建或更新后 `dictStore.loadXxx({ force: true })`
12. **SEO-like title**：`document.title = meta.title + ' - DataPay Admin'` 可选

## 九、风险与注意事项

| 风险 | 应对 |
|---|---|
| mock `getOrderStatusCount` 性能 | 内存 reduce 可接受，但避免频繁调用；Tab 切换不重拉计数 |
| 详情页串 id | 禁止纳入 keep-alive；或 tagsView key 拼 id |
| 富文本保存后丢样式 | wangEditor HTML 原样保存；详情页用 `v-html` 展示（或再次挂 editor 只读模式） |
| 封禁后仍能看到 | 列表要即时刷新 + 徽标更新 |
| 金额运算 | 全用整数分；前端任何加减都基于 fen，最后 fen2yuan 展示 |
| 订单类型与字段 | 非商品订单（type ≠ 5）没有 `address_snap`，详情页要条件渲染 |
| 权限指令未生效 | 检查 `permission.js` 指令已在 main.js 注册；mock permissions 必须包含对应字符串 |
