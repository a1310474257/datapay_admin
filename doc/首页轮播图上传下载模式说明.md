# 首页轮播图图片上传与下载模式说明

## 结论

首页轮播图图片采用 **“上传返回 objectKey、业务表仅保存 objectKey、访问时通过后端文件中转接口下载/预览”** 的模式。

这不是“前端直接保存公网 URL 并直链访问”的模式，而是受控访问模式。

## 涉及代码位置

- 页面：`src/views/operation/banner/index.vue`
- 上传组件：`src/components/UploadImage/index.vue`
- 上传 Hook：`src/hooks/useUpload.js`
- 轮播 API：`src/api/banner.js`

## 上传模式（写入阶段）

1. 轮播图表单使用 `UploadImage`，并传入 `use-object-key`：
   - `src/views/operation/banner/index.vue`
   - 示例：`<UploadImage v-model="form.image" folder="banner" ratio="3:1" use-object-key />`

2. `UploadImage` 在上传时调用 `useUpload().upload(file, folder, { returnObjectKey })`：
   - `src/components/UploadImage/index.vue`
   - 当 `useObjectKey=true` 时，`returnObjectKey=true`

3. `useUpload` 根据 MIME 类型选择端点：
   - 图片 -> `/admin/upload/image`
   - 视频 -> `/admin/upload/video`
   - 其他 -> `/admin/upload/file`
   - 文件：`src/hooks/useUpload.js`

4. `returnObjectKey=true` 时，上传返回值取 `data.objectKey`，并回填到 `v-model`（即 `form.image`）。

5. 提交轮播保存时，`form.image` 原样进入 `payload.image` 并发送到 `/admin/banners`：
   - `src/api/banner.js` 中 `toBackendPayload` / `createBanner` / `updateBanner`

## 下载/预览模式（读取阶段）

轮播列表展示图片时，不直接使用 objectKey，而是先做 URL 解析：

- 若值是 `http(s)` 或 `data:`，直接使用原值；
- 若以 `image/` 开头，拼接为：`/api/file/image?key={objectKey}`；
- 否则拼接为：`/api/file/{encodeURIComponent(objectKey)}`。

对应实现位置：

- `src/views/operation/banner/index.vue` 的 `resolveBannerImage`
- `src/components/UploadImage/index.vue` 的 `resolveImageUrl`

这说明图片访问统一通过后端 `api/file` 路由中转，由后端处理鉴权、签名或存储网关细节。

## 数据形态说明

- **数据库/业务字段（banner.image）**：保存 objectKey（示例：`image/2026/04/xx.png`）
- **前端展示地址**：运行时转换为 `/api/file/...` 中转地址
- **最终文件实体**：存放在对象存储（项目注释中说明为 BOS）

## 方案特点

- 优点：
  - 文件真实存储地址不直接暴露给前端；
  - 可在后端统一做权限控制、下载审计、过期策略；
  - 后续迁移对象存储厂商时，前端改动小。

- 影响：
  - 前端必须通过 `/api/file/*` 才能访问 objectKey 文件；
  - 若后端中转接口不可用，前端即使拿到 objectKey 也无法直接访问。

## 简要时序

1. 用户在轮播管理页选择图片  
2. 前端上传到 `/api/admin/upload/image`（经代理）  
3. 后端返回 `objectKey`  
4. 前端将 `objectKey` 存入 `banner.image`  
5. 列表展示时将 `objectKey` 转为 `/api/file/...`  
6. 浏览器请求后端中转接口完成预览/下载
